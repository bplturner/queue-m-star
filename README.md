# M-Star Queue Manager

A GPU-aware job queue and management dashboard for [M-Star CFD](https://mstarcfd.com) simulations. Submit, monitor, and manage CFD jobs through a modern web interface or REST API.

---

## Features

- **Web Dashboard** — Submit jobs, monitor GPU utilization, view real-time simulation progress with interactive charts
- **GPU-Aware Scheduling** — Automatically detects free GPUs and prevents resource conflicts
- **Multi-Version Support** — Manage multiple M-Star CFD installations side by side
- **Job Recovery** — Re-attaches to running simulations after daemon restart (no lost work)
- **Auto-Copy** — Automatically copy completed results to a destination path
- **File Browser** — Browse the server filesystem to select MSB files and output destinations
- **User Management** — Role-based access control with admin and user roles
- **AI Training** — Train PhysicsNeMo/PyTorch surrogate models from parameter sweep results (opt-in)
- **File Watcher** — Legacy intake from network queue directories
- **PDF Reports** — Generate reports from simulation statistics directly in the dashboard

## Requirements

- **Linux** (Ubuntu 20.04+ recommended)
- **NVIDIA GPUs** with `nvidia-smi` available
- **python3** (for MSB file unpacking)
- **mpirun** (OpenMPI, for multi-GPU jobs)
- **M-Star CFD** installed (any version 3.x or 4.x)
- **sudo** access (for service installation)

## Quick Start

### Option 1: Install from Release

```bash
# Download and extract the latest release
tar xzf mstar-queue-*.tar.gz
cd mstar-queue-*/

# Run the interactive installer (prompts for all settings)
./install.sh
```

### Option 2: Build from Source

```bash
# Clone the repository
git clone https://github.com/bplturner/queue-m-star.git
cd queue-m-star

# Build the release binary (requires Rust toolchain)
cargo build --release

# Run the installer
./install.sh
```

The installer will:
1. Create a system user and install directory
2. Prompt for all paths and settings (with sensible defaults)
3. Generate `config.toml` and systemd service
4. Optionally configure M-Star download credentials
5. Start the service

### Installer Options

| Flag | Description |
|---|---|
| `./install.sh` | Interactive installation (prompts for all settings) |
| `./install.sh --non-interactive` | Accept all defaults (for automated deployments) |
| `./install.sh --dry-run` | Preview what would be done without modifying the system |
| `./install.sh --help` | Show usage information |

## Configuration

All configuration is done through `config.toml`, generated by the installer. Key settings:

### Paths

| Setting | Default | Description |
|---|---|---|
| `install directory` | `/opt/mstar_queue` | Where the binary, config, and database live |
| `data_root` | `/opt/mstar_queue/data` | **Security boundary** — file browser and copy-to restricted to this path |
| `mstar_install_dir` | `/opt/mstar` | Where M-Star CFD versions are installed |
| `queue_directory` | `/opt/mstar_queue/queue/` | Drop MSB files here for automatic intake |
| `jobs_directory` | `/opt/mstar_queue/jobs` | Working directory for running simulations |

### Web Server

| Setting | Default |
|---|---|
| Port | `1111` |
| Max upload size | `500 MB` |

### Queue

| Setting | Default | Description |
|---|---|---|
| `max_concurrent_jobs` | `8` | Maximum simultaneous simulations |
| `default_mstar_version` | `latest` | Default solver version |
| `auto_requeue_on_restart` | `true` | Re-launch interrupted jobs after reboot |
| `startup_delay_secs` | `10` | Wait for NFS/GPUs before processing |

### Security

| Setting | Default | Description |
|---|---|---|
| `allowed_email_domain` | *(empty = allow all)* | Restrict registration to a specific email domain |

See [`config.toml.example`](config.toml.example) for the complete reference with inline documentation.

### AI Training (Optional)

To enable AI surrogate model training from sweep results:

```toml
[ai_training]
enabled = true
python_executable = "/path/to/venv/bin/python3"
```

Install the Python package:

```bash
cd python/ai_training && pip install -e ".[all]"
```

See [`docs/ai_training.md`](docs/ai_training.md) for full documentation, including dataset modes, model families, and CLI usage.

## Usage

After installation, open the dashboard:

```
http://<server-ip>:1111/
```

**Default credentials:** `admin` / `admin` — **change immediately** after first login.

### Submitting Jobs

**Via Web UI:** Click "New Job", browse the server for your `.MSB` file, select GPUs and solver version, then submit.

**Via REST API:**
```bash
# Login and get a token
TOKEN=$(curl -s -X POST http://localhost:1111/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"admin"}' | jq -r '.token')

# Submit a job
curl -X POST "http://localhost:1111/api/jobs/submit?name=my_sim&version=latest&gpu_ids=[0,1]" \
  -H "Authorization: Bearer $TOKEN" \
  --data-binary @simulation.msb
```

**Via File Watcher:** Drop an `.MSB` file into the queue watch directory. The daemon will automatically pick it up and launch the simulation.

### Service Management

```bash
sudo journalctl -fu mstar_queue.service   # View live logs
sudo systemctl restart mstar_queue.service # Restart after config changes
sudo systemctl stop mstar_queue.service    # Stop the service
sudo nano /opt/mstar_queue/config.toml     # Edit configuration
```

### M-Star Solver Updates

The dashboard includes an **Install Latest Version** feature (Settings → Solver Updates) that downloads the latest nightly build from M-Star. This requires download credentials, which the installer prompts for during setup. Credentials are stored in `.mstar_credentials` (chmod 600, not tracked by git).

## Architecture

| Component | Technology |
|---|---|
| Backend | Rust (Tokio async runtime) |
| HTTP Server | Warp |
| Database | SQLite |
| Frontend | Vanilla JS/HTML/CSS (no build step) |
| AI Training | Python (PyTorch / PhysicsNeMo) |
| Process Manager | systemd |
| GPU Detection | nvidia-smi |

**Key design decisions:**
- `KillMode=process` in systemd — daemon restarts don't kill running simulations
- Re-attach logic detects orphaned M-Star processes by inspecting `/proc/{pid}/cmdline`
- `data_root` acts as a configurable security boundary for all file system access
- Passwords are bcrypt-hashed; sessions use 64-character random hex tokens
