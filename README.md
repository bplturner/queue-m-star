# M-Star Queue Manager

A GPU-aware job queue and management dashboard for [M-Star CFD](https://mstarcfd.com) simulations. Submit, monitor, and manage CFD jobs through a web interface or by dropping `.MSB` files into a watched directory.

## Features

- **Web Dashboard** — Submit jobs, monitor GPU utilization, view simulation output
- **GPU-Aware Scheduling** — Automatically detects free GPUs and prevents conflicts
- **Multi-Version Support** — Manage multiple M-Star CFD installations side by side
- **Job Recovery** — Re-attaches to running simulations after daemon restart
- **File Watcher** — Legacy intake from network queue directories
- **Auto-Copy** — Automatically copy results to a destination path on completion

## Quick Install

```bash
# 1. Extract the release tarball
tar xzf mstar-queue-*.tar.gz
cd mstar-queue-*/

# 2. Run the interactive installer
./install.sh
```

The installer prompts for all configurable paths and settings with sensible defaults. Press **Enter** to accept each default, or type a custom value. No manual file editing is required.

### Installer Options

| Flag | Description |
|---|---|
| `./install.sh` | Interactive installation (prompts for all settings) |
| `./install.sh --non-interactive` | Accept all defaults (for automated deployments) |
| `./install.sh --dry-run` | Preview what would be done without modifying the system |
| `./install.sh --help` | Show usage information |

### What the Installer Configures

| Setting | Default |
|---|---|
| Install directory | `/opt/mstar_queue` |
| Web server port | `1111` |
| M-Star install directory | `/opt/mstar` |
| Queue watch directory | `/opt/mstar_queue/queue/` |
| Jobs directory | `/opt/mstar_queue/jobs` |
| Max concurrent jobs | `8` |
| Default M-Star version | `latest` |
| Job retention | `90` days |
| System user | `mstar_user` |

## Requirements

- **Linux** (Ubuntu 20.04+ recommended)
- **NVIDIA GPUs** with `nvidia-smi` available
- **python3** (for MSB file unpacking)
- **mpirun** (OpenMPI, for multi-GPU jobs)
- **M-Star CFD** installed in `/opt/mstar` (or custom path)
- **sudo** access (for service installation)

## Usage

After installation, the web dashboard is available at:

```
http://<server-ip>:1111/
```

**Default credentials:** `admin` / `admin` — change immediately after first login.

### Service Management

```bash
# View live logs
sudo journalctl -fu mstar_queue.service

# Stop the service
sudo systemctl stop mstar_queue.service

# Start the service
sudo systemctl start mstar_queue.service

# Restart after config changes
sudo systemctl restart mstar_queue.service

# Edit configuration
sudo nano /opt/mstar_queue/config.toml
```

### Submitting Jobs

**Via Web UI:** Click "New Job" in the dashboard, select your `.MSB` file, choose GPUs and version, then submit.

**Via API:**
```bash
curl -X POST "http://localhost:1111/api/jobs/submit?name=my_sim&version=latest&gpu_ids=[0,1]" \
  -H "Authorization: Bearer <token>" \
  --data-binary @simulation.msb
```

**Via File Watcher:** Drop an `.MSB` file into the queue watch directory (default: `/opt/mstar_queue/queue/`). The daemon will automatically create and launch a job.

## Building from Source

If you have the source code and Rust toolchain:

```bash
# Build release binary
cargo build --release

# Create a release tarball
./make-release.sh

# Or install directly from source
./install.sh
```

## Configuration Reference

The configuration file (`config.toml`) is generated by the installer. All values can be changed after installation — restart the service for changes to take effect.

See `config.toml` comments for detailed documentation of each setting.

## Architecture

- **Rust** binary with async I/O (Tokio)
- **Warp** HTTP server for the REST API and web dashboard
- **SQLite** database for job state
- **systemd** service for production deployment
- Process-level `KillMode` to preserve running simulations across daemon restarts
